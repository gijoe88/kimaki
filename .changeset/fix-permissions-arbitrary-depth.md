Fix permission prompts hanging the whole agent call chain when a subagent at depth 2 or deeper requests permission. Previously the depth ≥ 2 prompt was silently dropped by the per-runtime event filter, leaving the leaf session (and every ancestor waiting on it) stuck in `running` until manual abort. The root Discord thread now surfaces these prompts with a leaf-only label and a `(depth N)` suffix (shown only when depth ≥ 2 so depth-0 and depth-1 prompts stay visually identical). The existing Accept / Accept Always / Deny buttons and 10-minute TTL auto-reject now cover deep prompts too. Subagent text/tool display in the root thread stays depth-1 in this release; only interactive UI (permissions) crosses depth.

**Behavior change — "Accept Always" scope expansion:** clicking "Accept Always" on any permission prompt (depth-0 or depth-N) now auto-accepts future prompts for the same permission type and covered patterns across the whole root session tree — ancestors, siblings, current descendants, and descendants spawned later — without re-showing buttons. Previously "Accept Always" only affected the single leaf session that emitted the prompt. This is intended to remove the friction of re-approving the same pattern in every subagent; rules are scoped to the exact patterns from the original `permission.asked` event (no widening), only match the same permission type (an `edit` rule will never auto-accept a `bash` prompt), and are cleared when the root session ends. The rules are also persisted back to opencode via `session.update` on the root session and every currently-running descendant, so they survive bot restarts and apply even when the in-memory safety net is bypassed.

**Stale prompt cleanup:** when a subagent exits (idle, error, or deleted) while one of its permission prompts is still pending in the root thread, the prompt is now proactively dismissed with the status `_Subagent exited before answer._` instead of waiting up to 10 minutes for the TTL to auto-reject it. This covers the whole dying subtree (the exited session plus any of its descendants). Previously the prompt sat with live buttons until the TTL expired, which was correct but noisy.
